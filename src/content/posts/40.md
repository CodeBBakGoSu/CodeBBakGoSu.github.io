Codex 앱 베타 출시와 함께 추가된 **Codex Connections 기능**은 개발 workflow를 한 단계 끌어올리는 중요한 기능입니다. 단순한 SSH 접속 도구가 아니라, **원격 서버 자체를 Codex의 작업 환경으로 사용하는 방식**이라는 점에서 기존 방식과 큰 차이를 보입니다.

## Codex Connections란 무엇인가

![](/images/posts/40/1.jpg)

Codex Connections는 원격 서버를 Codex의 작업 환경으로 연결하는 기능입니다. 단순히 SSH로 접속하는 것이 아니라, **Codex가 직접 해당 서버에서 작업을 수행하도록 만드는 구조**입니다.

![](/images/posts/40/2.png)

  
  

### 기존 SSH 방식과의 차이

기존 SSH는 사람이 직접 접속해서 작업하는 방식입니다. 하지만 Codex Connections는 다릅니다.

-   SSH: 사람이 직접 명령 실행
-   Codex Connections: Codex가 대신 작업 수행

즉, 사용자는 명령만 내리고 실제 실행은 원격 서버에서 자동으로 진행됩니다.

### 단순 접속이 아닌 “환경 연결”의 의미

이 기능의 핵심은 "접속"이 아니라 "환경 선택"입니다. Connections를 통해 서버를 등록하면, 이후 Codex 스레드에서 **로컬 대신 해당 서버를 선택**할 수 있습니다.

## Codex Connections가 하는 일

Codex Connections 기능은 단순히 연결만 하는 것이 아니라, 실제 개발 작업 전체를 수행합니다.

### 파일 탐색 기능

원격 서버에 있는 프로젝트 파일을 탐색하고 구조를 분석할 수 있습니다.

### 명령 실행 기능

-   테스트 실행
-   빌드 수행
-   패키지 설치

모든 작업이 원격 환경 기준으로 실행됩니다.

### 코드 수정 및 작업 수행

Codex는 원격 저장소의 코드까지 직접 수정할 수 있습니다. 즉, 로컬로 클론할 필요 없이 바로 작업이 가능합니다.

## 사용 전 필수 조건

Codex Connections를 제대로 사용하려면 몇 가지 조건이 필요합니다.

![](/images/posts/40/3.png)

###   
SSH 키 기반 인증

비밀번호 방식은 거의 사용할 수 없습니다. Codex 내부에서 다음 옵션을 사용하기 때문입니다:

```
ssh -o BatchMode=yes
```

이 옵션은 비밀번호 입력을 차단합니다.

👉 따라서 반드시 **SSH 키 인증 방식**을 사용해야 합니다.

### ssh-agent 설정

SSH 키가 암호화되어 있다면 반드시 ssh-agent에 등록되어 있어야 합니다.

```javascript
ssh-add ~/.ssh/your_key
```

이 설정이 없으면 연결이 실패할 가능성이 큽니다.

### 원격 서버 codex CLI 설치

원격 서버에도 Codex CLI가 설치되어 있어야 합니다.

확인 방법:

```
codex --version
which codex
```

## Connections 설정 방법

### Settings > Connections 메뉴 설명

Codex 앱에서 다음 경로로 이동합니다:

```
Settings → Connections
```

여기서 서버를 추가할 수 있습니다.

### 필수 입력 값 정리

예시 설정:

```
Host total
HostName 192.168.1.4
User total
Port 22
IdentityFile ~/.ssh/total_a5000_ed25519
```

입력 항목:

-   Display Name (별칭)
-   HostName (IP 또는 도메인)
-   Port
-   Identity File

## 문제 발생 시 체크리스트

다음 항목을 확인하세요:

-   ssh 접속 가능 여부
-   BatchMode 테스트 성공 여부
-   codex CLI 설치 여부
-   ssh-agent 등록 상태
-   Connections 연결 상태

## 자주 묻는 질문 (FAQ)

### Q1. 비밀번호 SSH는 사용할 수 없나요?

A. 거의 불가능합니다. BatchMode 옵션 때문에 키 인증이 필수입니다.

### Q2. 로컬에 프로젝트 없어도 되나요?

A. 네, 서버에만 있어도 작업 가능합니다.

### Q3. codex CLI는 꼭 필요한가요?

A. 네, 원격 실행을 위해 반드시 필요합니다.

### Q4. GPU 서버에서도 사용 가능한가요?

A. 가능합니다. 오히려 가장 큰 장점입니다.

### Q5. 여러 서버 연결 가능한가요?

A. 가능합니다. Connections에서 여러 개 등록할 수 있습니다.

## 결론

Codex Connections 기능은 단순한 원격 접속 도구를 넘어, **개발 환경 자체를 확장하는 새로운 방식**입니다.

특히 서버 중심 개발, AI 작업, DevOps 환경에서는 매우 강력한 도구가 될 수 있습니다. 앞으로 Codex 생태계에서 핵심 기능으로 자리 잡을 가능성이 높습니다.
