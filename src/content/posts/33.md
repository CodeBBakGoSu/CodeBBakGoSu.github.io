# CORS(Cross-Origin Resource Sharing)의 역할

이거는 서버가 헤더로 '이 출처 요청은 허용해도 된다'라고 브라우저에게 알려주는거임

서버는 예를들어 이런식으로 내려줍니다

```
Access-Control-Allow-Origin: http://localhost:5173
Access-Control-Allow-Credentials: true
Access-Control-Allow-Methods: GET, POST, PUT, DELETE, OPTIONS
Access-Control-Allow-Headers: Content-Type, Authorization
```

따라서 그럼 브라우져단에서  
“아 이 서버는 [http://localhost:5173에서](http://localhost:5173%EC%97%90%EC%84%9C) 오는 요청을 허용했구나, OK~”  
하고 JS코드를 컴퓨터에서 실행시킵니다.

간단히 말해:  
• CORS는 “브라우저 ↔ 우리 백엔드” 통신 문제  
• 구글 OAuth 서버랑은 CORS 이슈가 없다 (브라우저 네비게이션/리다이렉트는 CORS 대상이 아님)

따라서

CORS와 구글 로그인에서 자주 나오는 실수

편하게 요약하면:  
• [https://accounts.google.com/](https://accounts.google.com/)... 으로 브라우저가 직접 이동하는 건 CORS와 무관  
• 문제가 되는 것은:  
• 프론트: [http://localhost:5173](http://localhost:5173)  
• 백엔드: [http://localhost:8080](http://localhost:8080)  
• 프론트에서 fetch("[http://localhost:8080/auth/google"](http://localhost:8080/auth/google")) 할 때  
→ 이때 백엔드가 CORS 허용을 안 해주면 에러 발생

따라서, Google Cloud Console에 [http://localhost:5173을](http://localhost:5173%EC%9D%84) 넣는다고 CORS가 해결되는 게 아니라,  
우리 백엔드 서버에서 CORS를 설정해줘야 하는 것입니다.

# OAuth 2.0

OAuth의 본질  
사용자의 비밀번호를 알려달라고 하지말고, 사용자가 직접 서비스 제공자(Google 등)에게 로그인하고,  
그 서비스가 '토큰'을 대신 발급해주면,그 토큰을 통해 제한된 권한으로 리소스에 접근하자.

즉  
• 우리가 사용자 비밀번호를 직접 저장/검증하지 않는다.  
• 대신 Google, GitHub, Kakao 같은 Identity Provider에게 위임한다.  
• 우리가 받는 것은 Access Token 같은 “권한 티켓”.

OAuth 2.0은 원래 Authorization 프로토콜에 가깝지만,  
OpenID Connect (OIDC) 라는 확장 규격을 사용하면 로그인(인증) 용도로도 쓸 수 있습니다.  
구글 로그인에서 흔히 사용하는 것이 바로:

OAuth 2.0 + OpenID Connect

입니다.

나중에 또 햇갈리면 다시 정리하러 와야겠다.

따라서 CORS 오류가 나면 프론트에서 구글을 거치고 리다이랙트로 떨구는 URL을 + 구글 콘솔에 이거 추가해주고

![](/images/posts/33/2.png)

```
# 프로덕션과 로컬 개발 환경 모두 지원
allowed_origins = [
    "https://gang-nang-bot.vercel.app",  # 프로덕션 프론트엔드 (실제 URL)
    "https://gangnangbot.vercel.app",  # 프로덕션 프론트엔드 (이전 URL)
    "http://localhost:3000",
    "http://localhost:8080",
    "http://127.0.0.1:3000",
    "http://127.0.0.1:8080",
    "http://localhost:5173",
    "https://gang-naeng-bot-fe.vercel.app"
]

app.add_middleware(
    CORSMiddleware,
    allow_origins=allowed_origins,
    allow_credentials=True,
    allow_methods=["*"],
    allow_headers=["*"],
)
```

이런식으로 관리를 해주어야 한다!
